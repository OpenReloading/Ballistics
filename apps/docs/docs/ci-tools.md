## Lint rules without an Oxlint counterpart

Oxlint replaced Biome's lint of JavaScript and TypeScript. These rules of Biome's set had no counterpart:
- No Oxlint rule: `noSvgWithoutTitle`, `noEmptyTypeParameters`, `noFlatMapIdentity`, `noThisInStatic`, `noUselessContinue`, `noUselessStringRaw`, `noUselessUndefinedInitialization`, `useSimpleNumberKeys`, `noStringCaseMismatch`, `noVoidTypeReturn`, `noDynamicNamespaceImportAccess`, `noImplicitAnyLet` (TypeScript's `noImplicitAny` covers most), `noRedundantUseStrict`, `noSuspiciousSemicolonInJsx`.
- Cognitive complexity (`noExcessiveCognitiveComplexity`, limit 15): Oxlint has none. Its cyclomatic `complexity` (classic, at most 20) runs on the whole repository instead, without exceptions; `packages/units`, `packages/locale-format`, `packages/schema`, `packages/statistics`, `packages/ballistics`, `packages/shot-groups`, `packages/importers` and `tooling/test-kit` hold the stricter simplicity rules of `packages/oxlint.logic.json` (complexity 10 and the others), which their `.oxlintrc.json` extends.
- Typed rules, which only a typed run reads (as in `packages/units`): `useLiteralKeys` (`typescript/dot-notation`), `useOptionalChain` (`typescript/prefer-optional-chain`), `useExportType` (`typescript/consistent-type-exports`), `useArraySortCompare` (`typescript/require-array-sort-compare`), `useAwait` (`typescript/require-await`; the untyped `require-await` also flags a concise async arrow such as `async () => run()`, which Biome's rule passes: about 40 of its 52 findings here).
- No Oxlint rule in the React, Next.js, test and Playwright domains (rules Biome ran for those packages): `useReactAsyncServerFunction`, `noPlaywrightMissingAwait`, `usePlaywrightValidDescribeCallback`. The others of those domains have their counterparts in `.oxlintrc.json` (the React override and the test override).
- Broader in Oxlint, so left out: `useSemanticElements` (`jsx-a11y/prefer-tag-over-role` also flags `role="status"` and `role="img"`).
- Covered elsewhere: `noUndeclaredDependencies` (knip), `noDuplicateParameters` and `noOctalEscape` (syntax errors in a module).

## Rules for workflows

- Every action is pinned to a full commit SHA with its version in a comment. Dependabot updates both.
- `permissions`: none at the workflow level, set per job. `persist-credentials: false` on every checkout.
- Every job has a `timeout-minutes` of about three times its median run, except `publish` in `release.yml`.
- `ci.yml` and `pr-title.yml` cancel a superseded pull request run (`concurrency`).
- `ci.yml` and `pr-title.yml` run on pull requests and on `merge_group` (for a merge queue on `main`, not enabled yet), and `ci.yml` also on push to `main` and every Monday at 04:00 Europe/Berlin. A pull request tests only the workspaces it changes and those that depend on them (`apps/web/scripts/ci-plan.mts` asks pnpm, `--filter "...[<base>]"`), every test group for a change outside the workspaces; every other event, the merge queue included, tests everything. `check` waits for every other job of `ci.yml` and fails when one failed, was cancelled, or was skipped where the plan cannot skip it. Every required check that a workflow produces reports under its own name on both events (`dependency-review` and `conventional` check the pull request only and succeed on `merge_group`). `SonarCloud Code Analysis` is a GitHub App check, not a workflow, and it does not report on `merge_group` (checked on the queue commit of a test merge, 2026-10-27); it is not a required check, so a merge queue does not wait for it.
- Tool images of `docker run` steps are set in the `env` block of `ci.yml` and `release.yml`. Dependabot does not read them: update them by hand.
- Jobs that publish or need secrets run only in `OpenReloading/Ballistics` (`if: github.repository == ...`).

## Repository settings (maintainers)

- Settings, General: Discussions on. Pull requests: merge and squash allowed, default squash message "Pull request title". "Automatically delete head branches" on.
- Settings, Actions, General: "Require actions to be pinned to a full-length commit SHA" on. Workflow permissions read-only, "Allow GitHub Actions to create and approve pull requests" on (release-please opens its release pull request).
- Release GitHub App (organization variable `RELEASE_APP_CLIENT_ID`, secret `RELEASE_APP_PRIVATE_KEY`), installed on the repository with Contents, Issues and Pull requests read and write: `release.yml` opens the release pull request with its token, so the required checks run without anyone approving them (without the App, see [Releases](release.md#flow)). The secret `RELEASE_PLEASE_TOKEN` is no longer used and can be deleted.
- Settings, Pages: source "GitHub Actions". Settings, Environments, `github-pages`: deployment branches `main` and the release tags (`*-v*`), no other entry.
- Settings, Advanced Security: dependency graph, Dependabot alerts and security updates, secret scanning with push protection, private vulnerability reporting. Code scanning: CodeQL default setup off (`codeql.yml` is the advanced setup; both at once are rejected).
- Rules, ruleset on `main`: pull request required (merge and squash allowed, no approval count, review threads resolved), signed commits, no force push or deletion, required checks `check`, `e2e` and `workflows` (`check` already stands for the other two). `conventional`, `dependency-review` and `SonarCloud Code Analysis` run on pull requests but are not required. Organization admins may bypass through a pull request.
- After the first release: the package `ballistics-api` set to public in its package settings.
