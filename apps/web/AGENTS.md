# @open-reloading/web

Next.js App Router (TypeScript, React). API at `API_URL` (default `http://localhost:3000`). May import `@open-reloading/core` for computation in the browser. Package rules: root `AGENTS.md`.

## Records and lists

- `/cartridges`, `/cartridges/[id]`: server components reading the API through `apiGet` in `src/lib/api.ts` (`'use cache'`, `cacheLife('days')`).
  - With the API reachable during `next build`, every cartridge page is prerendered. Without it the build passes and pages render on first request.
  - `PRERENDER=sample` (root `AGENTS.md`) limits that to the records of `src/lib/prerender-sample.ts` (`sampleIds`, `pickIds`, read by `staticIds` in `src/lib/api.ts`). At least one id per route: the ids the e2e specs and the smoke set open. Every other id renders on its first visit. An unknown id answers 404 (`ensureStatic = 'navigation'` in `[id]/layout.server.tsx`).
  - At run time an unreachable API throws, so cached pages stay.
- Home (`src/app/page.tsx`): the page bar's h1 visually hidden (`titleHidden`), the top bar shows the whole wordmark there (`Brand` `full` in `site-header.tsx`; other pages cut it to its mark), the Tools and Library panels from `sections` as cards in one row each (stacked below 48em), the Library cards each with its tabs as links and the record counts of the Database tabs from the list routes at build time.
- `/bullets`, `/bullets/[id]`, `/powders`, `/powders/[id]`: prerendered like the cartridge pages, from `GET /bullets` and `GET /powders`.
- `/cases`, `/cases/[id]`: the case records, prerendered like the cartridge pages, from `GET /cases` and `GET /cases/<id>`. List (`case-list.tsx`, rows in `src/lib/case-rows.ts`): manufacturer, name, cartridge, material, mass and stated water capacity; search, source. Record: the strip (`caseStrip`: material, mass, stated capacity), the Properties panel (`FieldTable`, `caseRowGroups` in `src/lib/record-fields.ts`: headstamp, primer pocket, flash hole, annealed), the cartridge link, the note and the Sources.
- `/primers`, `/primers/[id]`: the primer records, prerendered like the cartridge pages, from `GET /primers` and `GET /primers/<id>`. List (`primer-list.tsx`, rows in `src/lib/primer-rows.ts`): manufacturer, name, product number, size, magnum flag and compound; search, source. Record: the strip (`primerStrip`: manufacturer, size, compound), the Properties panel (`FieldTable`, `primerRowGroups` in `src/lib/record-fields.ts`: product number, magnum, cup, intended use and the published figures), the note and the Sources.
- `/targets`, `/targets/[id]`: the target face records, prerendered like the cartridge pages, from `GET /target-faces`, each face record, `GET /target-mappings`, `GET /disciplines` and `GET /federations` (rows and value groups in `src/lib/target-faces.ts`).
  - List (`target-face-list.tsx`): name, federation, distances, outer diameter, rings and the count of disciplines mapped to the face; search.
  - Record: the strip (federation, distances, outer diameter, black area, rings), the face drawn from the record (`target-face-drawing.tsx`, server SVG), the Rings panel (`FieldTable`: scoring values, ring diameters, inner ten), the Events panel (one row per face event with its target mapping, `faceEventRows`: federation, number, discipline or else the event name, stage, distance, gauge, shots, kind and scoring where an event has them, section, else the page the mapping's source cites) and the Sources.
  - The Events panel links each listed discipline to `/disciplines/[id]`.
  - "New face" in the page bar opens `/targets/designer`.
  - "Open in shot groups" links to `/groups?face=<id>`: a new sheet whose first group is scored on that face (`linkedFace` in `target-editor.tsx`). An id no face record has (`isFaceId` in `src/lib/face-records.ts`) opens the last sheet. With `&event=<event id>` (a sheet whose group stores another kind of event key is rejected as an invalid record) the group also takes that face event, so the group panel shows the discipline of its mapping and its federation.
- `/disciplines`, `/disciplines/[id]`, `/federations`, `/federations/[id]`: the discipline and federation records, prerendered like the cartridge pages, from `GET /disciplines`, `GET /federations`, `GET /caliber-classes` (the names of the classes), each record (caliber classes, rule books), `GET /target-mappings` and the face records of the stages (rows, the search and value groups in `src/lib/disciplines.ts`, lists in `discipline-list.tsx`). `/federations` is reached from the discipline list and records and counts as under the Database (`covers` of its entry in `src/lib/sections.ts`).
  - Discipline list: name, number, federation, distance, category, caliber classes, faces; search. `?org=<abbreviation>` (the federation record's link) keeps one federation's disciplines, shown as a removable chip in the search row.
  - Discipline record: the strip (federation, distance, category), number, section, page and caliber classes (`FieldTable`), the links to the federation, the rule book (the source of the record's `section`) and the international discipline, the Faces panel (one row per target mapping: the face drawn small and linked, event, stage, gauge, shots) and the Sources. "Open in shot groups" opens the first mapping's face and event. With two or more mappings each row of the Faces panel opens its own (Shot groups column).
  - Federation list: name, abbreviation, country, rule books, disciplines and faces. Federation record: abbreviation, country, member of, the rule books, its disciplines (linked, and the discipline list with `?org=`) and the faces they use.
- Lists: directory tables fed with every summary, searched and sorted in the browser (`directory-table.tsx`, `src/lib/directory.ts`: search, source, scope and sort in the URL, windowed rows. The rows of each list are in `src/lib/bullet-rows.ts`, `cartridge-rows.ts`, `case-rows.ts`, `primer-rows.ts` and `powder-rows.ts`).
  - `bullet-list.tsx`: row checkboxes and Compare to `/bullets/compare?ids=` (`bullet-compare-view.tsx` reads `ids` and the records in the browser, `bullet-compare.tsx`: the drawings panel with the unit switch and the bullet data table in the groups of `bulletDataGroups`, from `src/lib/bullet-compare.ts`, the `ids` parameter in `src/lib/compare-ids.ts`). Its `fits` parameter (the cartridge record's link) keeps the bullets that fit a cartridge by the CIP rule (`bulletFits` of core), shown as a removable chip "Fits <cartridge>" in the search row.
  - `cartridge-list.tsx`, and `powder-list.tsx` with the burn-rate order (`/powders?sort=-rate` lists the fastest first, powders without a curve last). `/powders/burn-rates` keeps the overlay in `burn-rate-compare.tsx`.
  - The tables have no filter in the table or its row: no column or facet controls, no range filters, no More filters. Cartridges, bullets, powders, firearms, disciplines, federations and target faces share one look (`DirectoryTable`: rows of 2rem, `unit`, `dim` for a value equal to the row above's, `breakBefore` for a group break, `phoneAction`, `onOpen`) and differ only in their columns. A link's scope that has no control is `?fits=` (bullets) and `?org=` (disciplines), a chip in the search row (`scope` of `DirectoryFilters`) that lifts it. `ListLoading`, `EmptyList` (names the search, source and scope set, `filterText` in `src/lib/lists.ts`, Clear filters resets them).
  - Search row: search, source, the scope chip, below 48em a Sort select (`sorting` of `DirectoryFilters`, the only sort there). A set source has the link-coloured border.
  - Row selection (bullets for Compare, powders for the burn-rate overlay): a click on a row opens its record, ticking is the row's checkbox only, also while rows are ticked. A shift click on a checkbox (Shift+Space from the keyboard) ticks or unticks the rows between it and the box clicked before, in the table's sorted order, skipping rows without a box and stopping at the maximum (`pickRange` in `src/lib/selection.ts`). The ticked rows are chips in the page bar's status line (`PickedChips`) with a Clear selection button, in the URL as `?pick=`.
- List sources: the bullet and cartridge lists add the browser's design records as Mine rows (`useUserRecords`, `list-sources.tsx`, rows in `src/lib/sources.ts`).
  - `SourceFilter` (a button with a checkbox per source and its count) in the URL as `?src=`, on every list. Powders have the one source OpenReloading (a powder design is found through the File menu's Open and the workbench's Powder card, not as a list row). Firearms: the example is OpenReloading, the firearms of this browser Mine. The bullet and cartridge lists show a Source column only with Mine rows: a Mine row's badge and Delete, a catalogue row blank. A cell without a value shows n/a. Below 48em Delete is at the end of the row (`phoneAction`).
  - The designers open `?record=<id>` from the browser store (`use-record-link.ts`).
  - New records and photos get `crypto.randomUUID()` ids (`newId` in `src/lib/new-id.ts`); older ids stay valid, except a bullet's or cartridge's (a UUID is required, so a load can refer to it: the record fails the schema and stays in the store as an invalid record). Open and Import report references to missing user records with `refNote` (`src/lib/user-data.ts`, `checkUserRefs` of the schema) and keep the records.
- Cartridge record (`components/cartridge-record.tsx`, rows from `src/lib/cartridge-record.ts`):
  - Four fact cards (`RecordFacts`). The mm or in switch in the heads of the Cartridge and Chamber panels.

A drawing keeps the room and the scale of the other length unit's (one frame width and height for both units, `CartridgeDrawing` with `side`).
  - The button link "Bullets (n)" to `/bullets?fits=<id>` (`cartridge-bullets.tsx`), not printed.
  - A record without values shows the Gap badge (`GapBadge` in `standard-badge.tsx`, also in the cartridge list) and the line "No dimensions or pressures in this record". No unit switch, no Open in designer.
- Record frame (`components/record-page.tsx`): page bar with badges and the actions of `record-actions.tsx`, grid of figure (optional), values and side, then the Sources section (`components/sources.tsx`: `Sources` in full, `SourceTitles` for the lines of the workbench and the trajectory form).

- Bullet record: the Drawing panel (mm or in switch in its head), the Ballistic coefficients table (`CoefficientTable`) and the Cartridges panel (`bullet-cartridges.tsx`, filter over the names) left, the Bullet data panel whole at the right (`FieldPanel`: symbol, quantity, value and unit per row, a group filter, search over 20 rows, groups from `bulletDataGroups`). ## Workbench and designers

- `/workbench` and the designers: calculator workspaces (`src/components/workspace.tsx`): input panels, results with readouts and tabs. Below 48em tabs Inputs (workbench: Load) and Results. Designers: no tabs, their drawing sticky above a property grid (`property-grid.tsx`).
- `/workbench` files in `src/components/`:
  - `workbench.tsx`: composition.
  - `use-workbench-load.ts`: the state and actions (records, seating, ladder, run). The cards read them through `LoadContext`, the result side through `ResultContext` and `InputEcho` (`workbench-context.ts`).
  - `workbench-inputs.tsx`: the input cards, start card and checklist. `workbench-figure.tsx`: the cartridge figure. `workbench-readouts.tsx`: readouts, warnings, limits, the ladder strip and table.
  - `workbench-results.tsx`: the result tabs. `workbench-outcome.ts`: result types and helpers.
- Workbench: a full-window frame from 62em with the cards Cartridge, Powder, Bullet and Gun. From 75em Cartridge and the cartridge figure in the first column, Powder, Bullet and Gun in the second. The figure's drawing fills the card's free height and width. In a window lower than 45em (`shortFrame`) the burn-rate figure (`BurnFigure`) takes the figure's place under Cartridge, and the cartridge figure is the result tab Cartridge (`FigureTab` of `workbench-figure.tsx`, `panelColumns` in `workbench-inputs.tsx`). Below 75em one flow in the order of the markup: Cartridge, figure, Powder, Bullet, Gun. Start card "Start a load" for a new load. Below 48em a third tab "Range" (`workbench-range.tsx`).
- The results start with one line: the load, the notice and a fixed slot for the warnings (notice and slot not printed). Then the key tiles (peak pressure with its share of the limit and a bar, muzzle velocity, energy), the other readouts as a two-column list beside the burn-rate figure (in a low window, `shortFrame`, three columns, the figure in the inputs' second column), the ladder steps as one row that scrolls sideways. An error takes the place of the tiles and the list.
- Chamber volume note: a run whose volume is not a measured case capacity (`volumeMeasured` of `src/lib/input-defaults.ts`: a capacity entered for the cartridge and the volume field still holding what it gives, its followed default or the seated bullet's) shows the info `Message` "Chamber volume not measured" under the results head (`DesignNotes` in `workbench-results.tsx`) and the same sentences in the printed report's sub line and the load sheets' note (`volumeNoteText`). A record's capacity, a chosen capacity record and a typed volume are estimates. The Range tab has no note.
- Chart: the toolbar holds the quantity switch, the x axis switch and Data. Reference lines at 85 % and 75 % of the limit (`referenceLines`). The y axes share one count of intervals (`alignedAxes`).
- Page bar of the workbench (`workbench.tsx`, `Toolbar` in `workspace.tsx`): the load switcher (a menu of the open loads, Rename this load and Saved loads) and New load, Run, a status block of fixed width (the result, the file state), then Open, Save, Search, Copy link, Print and the Safety icon. From 75em Search, Copy link and Print are icons named by their text.
- Ladder table (charge ladders of more than one step): lot rows under each charge, one at a burn rate lower and one higher by a stated percentage (3 % by default, `src/lib/lot-rows.ts`, the model page `apps/docs/docs/models/interior-pressure-range.md`). `use-lot-rows.ts` asks the API for each lot as a ladder once the tab was opened or a print asked for it, after a pause when the percentage changes, and keeps the last answer of the run until the next. `lot-rows.tsx` holds the percentage and the optional target barrel time (ms, a line on the chart, not stored), `lot-chart.tsx` the barrel time against charge with a band between the shortest and longest barrel time of each charge's rows. The report prints the chart and the table with the lot rows. The percentage and the target are not part of share links or load files. The page says barrel time is a computed value.
- Result tabs: Chart, Cartridge (the figure, only in a low window, `shortFrame`), Ladder table, Trajectory, Measurements, Groups, Notes, Barrel length (`barrel-length.tsx`, `use-barrel-study.ts`, `src/lib/barrel-length.ts`) and Powders (`powder-compare.tsx`, `use-powder-compare.ts`, `src/lib/powder-compare.ts`, the HTTP client in `src/lib/api-client.ts`, `src/lib/batch.ts`). Those that do not fit go in a More menu (no aside).
- Open and Save in every page bar with user records (`file-menu.tsx`, `FileMenu`): Open lists This browser (the saved records, on the workbench the Saved loads drawer), File (Open file, Import, Paste JSON) and the page's Examples (workbench: Example load, Reset load). Save saves in one click; its chevron "Save options" holds Save as, Copy share link, Copy JSON, Export all and the workspace folder. A bullet's or a firearm's single-record file and JSON, and a bullet's share link, also carry the user manufacturer record the record names (`makerRecordsOf`); Open and a shared link keep it in the browser unless one of its id is stored. On the workbench it also holds Download for the API and Copy JSON for the API (`apiData` of `FileMenu`, `toApiLoad` in `src/lib/load-record.ts`): the load with every solver value of that moment typed, the cartridge and bullet as catalogue references (a design's values stay typed), and no firearm, capacity, chronograph series or seating and temperature ladder, so `POST /v1/interior/load-file` runs it as it is. Save, Save as and the browser copy still store the typed keys only (`apps/web/test/api-load-file.test.ts`). Below 75em both are rows of the Page actions panel.
  - The browser store (`src/lib/user-store.ts`) is a versioned IndexedDB: `upgrade` brings a new or older database to `version` without touching a record (`test/user-store-upgrade.test.ts`, `fake-indexeddb`). A record that fails the schema stays in the store (`validRecords` in `src/lib/user-data.ts` returns it as stored with the schema's error). - Manufacturer fields (the bullet designer and the firearm editor, `manufacturer-input.tsx`, `use-manufacturers.ts`, `src/lib/manufacturers.ts`): an autocomplete over the catalogue's and the browser's manufacturers. Leaving the field or choosing an option turns the text into a reference: the manufacturer it names (name or alias, case, accents, spaces and hyphens ignored; catalogue before user), else a new user record of kind `manufacturer` stored at once (`referTo`). The record keeps only the name. Until the catalogue's list has loaded, leaving the field asks for it again; a name no user manufacturer matches and the catalogue cannot be checked against gets no reference and no record, and the field shows the reason (`referTo` with `catalogueKnown` false).
- A saved load is the schema's `Load` in stored units (`src/lib/load-record.ts`: `toLoad` from the workbench state, `fromLoad` back; user record kind `load`, no `name` of its own). It keeps the references to the cartridge, firearm, bullet and powder, the charge, the case record (`case.record`, chosen in the Cartridge card's More), the primer record (`primer.record`, a `catalogue:` reference chosen next to it in `primer-choice.tsx`, listed from `GET /primers`; the older primer maker and model text is refused by the schema, no migration before 1.0; the file for the API leaves it out) with the primer lot, the case capacity (a `catalogue:` capacity chosen in the Cartridge card, or the measured one as a user record of kind `caseCapacity` that Save stores with the load, `storeLoad` and `measuredCapacityId` in `src/lib/load-record.ts`), the seating, the ladder, the notes, the chronograph sessions (`sessions`, references) and, under `analysis.overrides`, only the solver values the user typed. A value the powder record, the bullet record or design, the gun, the Settings defaults, a followed default or the seating gives again on opening stays out (`givenKeys`), and opening fills it from there: the fields start as a link's do, the records fill the rest, the typed values stay (`choosePowder` with its `keep` set). A value that a reference cannot name (a firearm whose id is no UUID, such as the example rifle) is saved as typed. Old records and files (kind `workbenchState`, `siValues`) are refused by the schema with a message that says so.
- Notes on a saved load (`src/lib/load-notes.ts`, `src/components/load-notes.tsx`, rules in `loadNotes` of core, `apps/docs/docs/models/load-notes.md`): the Notes tab holds the lots (powder, primer, case: `Load.powderLot`, `primer.lot`, `case.lot`) and the notes, and each session on the Measurements tab shows its own. Each session keeps a snapshot of the lots, the seating and the chosen firearm's round count (`Load.snapshots`): a session without a stored one shows the load as it is now, and Save fixes it (`onStored`). A note is dismissed per session and the dismissal is part of the snapshot. The round count threshold is the firearm's `noteAtRoundCount` (firearm editor). Notes use `Message` (info) and state values and sessions, no verdict.
- Open loads in the page bar's load switcher and the Saved loads drawer (`use-load-tabs.ts`, `load-tabs.tsx`, `saved-loads.tsx`, `src/lib/load-tabs.ts`).

The peak pressure's note and the line under the tiles (screen only, `band-line`) then show the 5th to 95th percentile of pressure and velocity and that they cover input tolerances only. Over budget, the corner-case range stays and the line says so. The limit check keeps the corner-case range.

## Pages edition

A static site without a server for GitHub Pages: the web app with the records as data files and the simulations in the browser, the docs site, the licenses. `pages.yml` builds it from `main` and deploys it at the site root. `ci.yml` does not build it.

- `PAGES_BASE_PATH` (`''` or a path such as `/Ballistics`) set (`next.config.ts`): `output: 'export'` under that base path with `trailingSlash`, without Cache Components and Partial Prefetching (Next 16.4 exports only without them, `'use cache'` through `experimental.useCache`), no redirects.
  - `pageExtensions` leaves out the `*.server.ts(x)` route files: the forwarding route and the record pages' `ensureStatic` layouts. A route-segment option one edition rejects goes into such a file.
  - `NEXT_PUBLIC_PAGES_BASE_PATH` is the base path in the browser (`src/lib/edition.ts`: `pagesBasePath`, `basePath`). A plain `<a href>` or asset URL to an app path takes `basePath`. `Link` and the router add it themselves.
  - `staticIds` prerenders every record (`PRERENDER=sample`: see the static loop below) and fails without the API.
- `apiFetch` of this edition: `src/lib/static-api.ts`. The server edition aliases it to `src/lib/no-static-api.ts` (`next.config.ts`), so its chunks hold neither the data file reader nor the compute worker.
  - GET: lists from `catalogue/index.json` under `<base>/api/` opened with `openCatalogue` (`@open-reloading/api/catalogue`), the code the API's routes run, so paging, `q`, the filters (`table`, `manufacturer`, `cartridge` (powder tables, cases), `size` and `compound` (primers), `federation`, `discipline`, `face`), order and the refusals are the API's; a record from `<kind>/<id>.json`. Checked against the API by `test/static-api.test.ts`.
  - POST `interior` and `interior/charge-target`: validation, runs and answers of `@open-reloading/api/compute`, each compute task in a Web Worker of its own (`src/lib/compute.worker.ts`), terminated at the API's task deadline (503 `timeout`). The 64 KiB body cap of the forwarding route.
- `PAGES_URL`: the site's origin (docs `url`, the web app's `metadataBase` and social image, which the server edition leaves out).
- Root `PAGES_BASE_PATH=<path> npm run pages:build` (`tools/src/pages.ts`, after the root `npm run build`): starts the API over the catalogue of the data bundle (`@open-reloading/api/static`), builds this edition against it with `PRERENDER=full`, deletes each page's `__next._full.txt` (a copy of its `index.txt`, never requested by the export's client), writes the data files (`writeStaticApi`: the catalogue index and one file per record), builds the docs site into `docs/` (its code reference under `docs/library/`), copies LICENSE, NOTICE and `data/LICENSE` and writes `.nojekyll`. Output: `pages/` at the repository root (git-ignored). It deletes `.next` before and after the build: a Turbopack cache of one edition fails the build of the other, so the server edition builds from nothing afterwards.

The data files are what the browser reads; the server side of a record page reads the API over the catalogue of the data bundle, which this process runs in-process for the length of the run. Ctrl+C ends both. `next dev` logs React warnings (duplicate keys in source lists, image sizes) that the production build does not.
  - `npm run static:build` at the root (`pages:build` with `PAGES_BASE_PATH=` and `--sample`): the export at the site root in `pages/`, `PRERENDER=sample` (the inherited value is never used, `pages:build` without `--sample` always builds every record), no docs site, about 85 MB in about 15 s. - Mantine CSS:
  - Imported per component in `src/app/layout.tsx` from the `*.layer.css` files. Add the file of every new Mantine component there, after the files it builds on.
  - `layers.css` (imported first) puts the layer `base` below `mantine`. The element defaults of `globals.css` (links, headings in `main`, tables, form fonts) sit in `base`, so Mantine components and their props win over them. Every other rule of `globals.css` is unlayered and wins over Mantine.
- Tokens: font sizes, headings and breakpoints in `theme.ts`. Spacing steps 0.25, 0.5, 0.75, 1 and 1.5rem in `globals.css`.
  - Screen text takes the theme sizes (`--mantine-font-size-*`, `--mantine-h*-font-size`). Outside them: sub text in `em` of its line, print sizes in `pt`, 16 px inputs on touch screens (smaller ones zoom the page on focus in iOS Safari) and the shot groups toolbar's 16 px icon slot, SVG text scaled with its figure, the ECharts text in px (11 and 12), and the Range tab's 2rem hero number.

- Theme: the system setting until the header switch or Settings, General stores `light` or `dark` (System stores `auto`) in `localStorage` (`theme`).
  - An inline head script (`colorSchemeScript`) sets `<html data-mantine-color-scheme>` before the first paint.
  - Colours are the tokens of `globals.css`. Mantine's body, text, anchor and default colours read them. Drawing colours are `--draw-*` tokens. The dark rule is screen-only, so print stays light.

  - A delete that can be taken back (a firearm, a target sheet, a group) asks nothing and calls `offerUndo`.
- Units and number formatting: `src/lib/units.ts` (values held in SI, fixed decimals, no grouping).
  - Stored units (mm, g, bar, degC) to SI and back: `toSi` and `fromSi` of `@open-reloading/schema`, never a factor written in place. `test/unit-literals.test.ts` fails on a factor literal in the API or web sources, except the time, byte and pixel lines it lists.
- Unit suffix of a field: `NumberField` switches that field only, in memory (`src/lib/field-unit.ts`).

## German terms

- `src/i18n/german-terms.json`: the term table of the German interface, one row per term with its key, English term, group, status (`verified`, `disputed`, `unverified`), the German word, and its sources as a document id and a place (section or page), never a passage. The document ids and their editions are the file's `sources`.
  - Verified: one German word and at least one source. Disputed: `german` is null, at least two candidates, each with its own source; the owner picks one. Unverified: a candidate or null, and a note on what was searched. A candidate is never a source.

## Streamed pages and the Mantine patch

- In a build made without the API the list pages stream. React 19.3 reveals a streamed boundary up to about 300 ms after the first paint.
- A provider above the page whose context value changes after mounting (Mantine's `AppShell` does, `UnitsProvider` did) makes React client-render the waiting boundary. A hidden `div#S:n` copy of the page stays until the reveal.
- Providers above `main` keep one context value for the page's life. `useUnits` reads a store behind a constant context.
- The page sits in `AppShell.Main` only because `patches/apply.mjs` (root `postinstall`, the Dockerfiles copy `patches/` before `npm ci`) memoizes AppShell's context value in `@mantine/core` 9.7.2.
- A Mantine upgrade that changes `AppShell.mjs` or `AppShell.cjs` stops the install. Check whether Mantine fixed the context value (upstream links in `patches/apply.mjs`), then remove the patch or adapt it.
- `npm run dev` and `npm run build` here run `node ../../patches/apply.mjs --check` first and stop when the installed files lack the patch (after a rebase onto the patch without `npm ci`).

## Commands (this directory, or `-w @open-reloading/web` from the root)

- Dev server: `npm run dev`
- Build: `npm run build` (standalone output in `.next/standalone`)
- Type check: `npm run typecheck` (generates route types first)
- Test: `npm test` (Vitest, `test/`)
- Prerender check after a build against a running API: `node scripts/check-prerender.mts`, with the `PRERENDER` value of the build. `sample` checks the lists and the sample records, else every record.
- Build workers: `next.config.ts` caps the static generation workers at 8 (`experimental.cpus`, `BUILD_WORKERS` for another number). The default is one per hardware thread but one.
- JavaScript budget: `npm run check-weight` after a build (CI: the `e2e` job, after the web build). Per route of `.next/app-path-routes-manifest.json` it sums the gzip level 9 bytes of each JavaScript file once, as `initial` (root main and polyfill files, the client chunks of the page and its layouts) and `total` (`initial` plus the lazy chunks of the page's `react-loadable-manifest.json`), and fails when a route is over the `budget` of its group in `weight-budget.json`, or is in no group, or a group lists a route the build lacks. The `routes` values in the file are the recorded weights the job summary's change column compares with. Server edition only (the Pages edition is not measured). The number does not depend on the API, `PRERENDER` or the build directory. A budget is the largest recorded value of its group plus 2 %, rounded up to 1000 B: raise it only in a pull request that says why, and record the values then. A new route goes into a group, or a new group.
- What a CI run or a local run must build, from the changed files: `node scripts/ci-plan.mts`. It prints `check=`, `e2e=`, `web=` and `prerender=`. Rules in the script, test `test/ci-plan.test.ts`.
  - CI: `EVENT_NAME`, `BASE_SHA`. Local: `--stamp apps/web/.next/ci-plan-stamp`, `--require full`.
  - After a build on a clean tree: `--write-stamp apps/web/.next/ci-plan-stamp --prerender <mode>`.
- Build cache: `.next/cache/turbopack` is reusable between builds. `.next/cache/fetch-cache` holds API responses (`cacheLife('days')`: a warm build would serve old record data), so `prebuild` deletes it and CI never caches it.
- Image: `docker build -f apps/web/Dockerfile .`, or `docker compose build web`. It builds the packages the web app imports, the API package and `@open-reloading/data` only as far as their entries (`tsconfig.browser.json`, `tsconfig.plausibility.json`), and copies the sources they reach. `test/dockerfile.test.ts` fails when a web import has no build or copy line there. A new import of one of those entries, or a file one of them reaches outside the copied folders, needs the Dockerfile's `COPY` lines.
